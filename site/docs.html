Install

Python 3.10 or newer, plus ffmpeg on your PATH.

# dependencies and the headless browser pip install -r requirements.txt python -m playwright install chromium # one-time data download (free, ~700 MB with 3km population) python data/download_data.py --natural-earth --music --kontur 3km # confirm the machine is ready — GPU, encoder, data, upstreams python -m worker doctor

On Windows, ffmpeg comes from winget install Gyan.FFmpeg. doctor prints the WebGL renderer — if it says SwiftShader you are on software rendering and frames will be several times slower.

Your first film

Two ways in. The dashboard is the quicker one:

python -m worker serve # http://127.0.0.1:8000

Search a place or shift-drag a box on the map, tick the overlays you want, paste a script, press Render. Progress, preview frames and the finished video all appear in the Queue tab.

Or drive it from a file, which is what you want once you are making these repeatedly:

python -m worker render --job examples/indus.json

Tick at least one overlay or write a script. With neither, you get a moving map and nothing else — the layers and the narration are what make it a documentary.

The job file

One JSON document describes a film.

KeyWhat it does
bboxRegion as [west, south, east, north] in EPSG:4326
overlaysAny of satellite, satellite_after, weather, population, borders
date / date_endImagery date; both set gives a before/after cross-fade
narrationThe script. This sets the film's length
shotsOptional camera moves: hold, flyto, orbit, path
beatsOptional explicit overlay timeline
vector_stylefiord (default), dark, positron, liberty, bright
label_densityfull, balanced, minimal, none

Leave shots out and a sensible flyover is generated for the region. Leave beats out and overlays are cued from the words in your script.

The beats timeline

Every render writes output/<job>/beats.json — the mapping from time to camera to visible overlays. It is generated from the script, and you can edit it and feed it back.

{ "fps": 30, "frames": 1980, "beats": [ { "t": 0.0, "duration": 4.53, "overlays": { "borders": 1.0 }, "text": "Pakistan is a country built around a single river." }, { "t": 35.05, "duration": 5.25, "overlays": { "population": 1.0 }, "text": "Nine out of ten Pakistanis live within reach of this water." } ] }

Once introduced, a layer stays on at lower opacity rather than snapping off — a layer that flashes on and vanishes reads as a fault, not an edit.

Hosted queue Studio and above

The system splits in two. A small dashboard runs on a cheap host and holds the job queue; your own machine polls it, renders locally, and uploads the finished file.

# on the host — UI and queue only, no rendering python -m worker serve --no-worker --host 0.0.0.0 # on your machine — claims jobs and renders them python -m worker poll --url https://your-app.example.com --token SECRET

The hosted side installs three packages and never renders anything, which is what keeps it inside a free tier. Set SPATIALDATA_TOKEN on both ends to require a shared secret.

Licence

A licence covers the software on the machine count for your tier. The films you render are yours, including commercially, with no revenue share and no per-render fee.

  • Solo — one person, one machine
  • Studio — up to five render machines, hosted queue included
  • Broadcast — unlimited machines, custom layers, source access

Fourteen day refund. Render something first.

Attribution

The data sources are free but not unconditional — most require credit. The renderer handles that for you: a compact credit is burned into the corner of every frame automatically, naming only the sources that render actually used.

Two things stay your responsibility:

  • If you use the bundled music, keep the composer credit in your description — the tracks are CC BY.
  • If you redistribute the underlying data rather than a video of it, the source licences (ODbL, CC BY) apply to that distribution.
